# C4 diagram-specific failure modes

This file supplements `references/common-issues.md` for mermaid `C4Context`, `C4Container` and `C4Component` diagrams.

## Type-specific issues

### Relationship text and lines vanish on a dark theme

mermaid draws every relationship line, label and arrowhead, and every boundary border and label, in `#444444` as SVG attributes. No theme variable reaches it. It is 9.74:1 on white and 1.92:1 on the zinc-dark ground.

**Detection:** relationship labels and lines barely visible on a dark ground.
**Fix:** theme-level. zinc-dark repaints the attribute with themeCSS (`[stroke="#444444"]`, `text[fill="#444444"]`). A new dark theme needs the same rules (`scripts/tests/test_theme_contrast.py`, `hardcoded_failures`).

### White text on a light box

Every C4 box draws its text `#FFFFFF`. Five default fills are too light for it: external system `#999999` (2.85:1), container `#438DD5`, external container `#B3B3B3`, component `#85BBF0` and external component `#CCCCCC`.

**Detection:** white box text that is hard to read on grey or pale blue.
**Fix:** theme-level. Both zinc themes give those boxes `#18181B` text with `.person-man:has([fill="…"]) text` and keep the C4 fills. The selector needs CSS `:has()`; a renderer without it falls back to white text.

### Relationship labels sit on their lines

C4 puts a relationship label at the middle of its line, so the text overprints the line and sometimes the arrowhead, and a line can cross an unrelated box. No setting routes round them.

**Detection:** label text crossed by its own line, or a line through a box it does not connect.
**Fix:** known limit. Shorten labels, or reorder the declarations so connected elements sit next to each other.
